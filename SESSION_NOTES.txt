ATS SCORING ENGINE (apps/ats/engine.py)
----------------------------------------
score_resume(resume_data, jd_text) → dict with:
  - overall_score      : weighted average (40% keywords, 25% sections, 20% format, 15% readability)
  - keyword_score      : keyword match rate vs JD top 30 keywords
  - section_score      : presence check for contact/summary/experience/education/skills/projects/certs
  - format_score       : formatting issues (missing LinkedIn, weak phrases, summary length)
  - readability_score  : word count, power verb usage, filler words
  - matched_keywords   : list of JD keywords found in resume
  - missing_keywords   : list of JD keywords NOT in resume
  - section_analysis   : per-section pass/fail dict
  - formatting_issues  : list of formatting problems
  - recommendations    : up to 15 actionable improvement tips


AI ASSISTANT (apps/ai_assistant/openrouter.py)
-----------------------------------------------
Functions:
  chat(history, message, resume_context) → (response, tokens, model)
  improve_bullet_points(bullets, job_title, industry) → (improved_text, tokens, model)
  generate_summary(resume_data, job_title, jd_text) → (summary, tokens, model)
  tailor_resume_suggestions(resume_data, jd_text) → (suggestions, tokens, model)

Rate limiting: per-user daily counter (ai_requests_today), resets at midnight UTC.
Admin can override via AppSettings: OPENROUTER_API_KEY, OPENROUTER_MODEL, AI_ENABLED,
AI_MAX_REQUESTS_PER_DAY.
API key NEVER sent to frontend.

HOW context_processors.py WORKS
---------------------------------
File: apps/accounts/context_processors.py

  from django.conf import settings
  def google_oauth_configured(request):
      configured = bool(
          getattr(settings, 'GOOGLE_CLIENT_ID', '') and
          getattr(settings, 'GOOGLE_CLIENT_SECRET', '')
      )
      return {'google_oauth_configured': configured}

Registered in settings.py under TEMPLATES → OPTIONS → context_processors:
  'apps.accounts.context_processors.google_oauth_configured'

Used in templates as:

    <a href="/accounts/google/login/" class="social-btn">Continue with Google</a>
  {% else %}

BUG FIXED: Drive page showing "Connect Google Drive" after login
-----------------------------------------------------------------
SYMPTOM: Visiting /drive/ after email/password login appeared to ask for login again.

ROOT CAUSE (2 issues):
1. SOCIALACCOUNT_STORE_TOKENS was not set — allauth 65.x requires this to be True
   explicitly, or it does NOT save OAuth tokens to the SocialToken table.
   Result: has_google_account=True but has_token=False → "Re-authorize Drive Access" prompt.
   For email-only users: has_google_account=False → "Connect Google Drive" prompt that
   looked like a login screen.

2. UX confusion: The Drive page's "Connect Google Drive" card didn't explain the user was
   already logged in — it looked like another login wall.

FIXES APPLIED:
  ats_builder/settings.py:
    Added: SOCIALACCOUNT_STORE_TOKENS = True
    (Now allauth will store access_token + refresh_token in SocialToken table)

  templates/drive/files.html:
    - "Connect Google Drive" section now shows logged-in email and explains this links
      Google to the existing account (no data is lost, user stays logged in)
    - Added conditional google_oauth_configured check for the link button
    - "Drive Access Needed" section text clarified
    - Stale SocialAccount entries (without tokens) cleared from DB

DATABASE CLEANUP:
  python manage.py shell → SocialAccount.objects.all().delete()
  (2 stale Google accounts cleared — they had no SocialToken, just extra_data with ID token claims)
  Users will re-link via the Drive page → Get fresh tokens with access_type=offline

ALLAUTH VERSION NOTE:
  Installed allauth is 65.19.1 (NOT 0.61.1 as in session notes — pip upgraded it)
  Settings ACCOUNT_LOGIN_METHODS, ACCOUNT_SIGNUP_FIELDS are still supported in v65.
  SOCIALACCOUNT_STORE_TOKENS=True is a v65-compatible setting.

BUG FIX: "+ Add Project", "+ Add Internship", "+ Add Experience", etc. Buttons Not Working
-----------------------------------------------------------------------------------------
SYMPTOM: Clicking "+ Add Project", "+ Add Internship", "+ Add Education", "+ Add Experience",
or any "+ Add ..." item button in the builder left panel did nothing and threw a JS error.

ROOT CAUSE:
  In `templates/resume/builder.html`, `renderList(containerId, arr, renderer)` contained:
    const div = document.createElement('div');
    div.innerHTML = renderer(item, i);
    cont.appendChild(div.firstElementChild);

  Card renderer functions (`renderProjCard`, `renderExpCard`, `renderEduCard`, `renderCertCard`,
  `renderAchCard`, `renderPubCard`, `renderVolCard`, `renderInternCard`) return DOM Nodes
  (`HTMLDivElement` objects), NOT HTML strings.

  Assigning a DOM Node to `div.innerHTML` implicitly stringified the node to `"[object HTMLDivElement]"`.
  Consequently, `div.firstElementChild` evaluated to `null`, causing `cont.appendChild(null)` to throw
  `TypeError: Failed to execute 'appendChild' on 'Node': parameter 1 is not of type 'Node'`. This crash
  halted JS execution immediately on button click.

FIXES APPLIED:
  `templates/resume/builder.html`:
    1. Updated `renderList(containerId, arr, renderer)`:
       - Checks if `renderer(item, i)` returns an `instanceof HTMLElement`.
       - If DOM Node: appends directly via `cont.appendChild(res)`.
       - If string: sets `div.innerHTML = res` and appends `div.firstElementChild`.
    2. Updated `updateEntry(key, i, field, val)`:
       - Dynamically updates the left panel entry card header title live as the user types
         in title, company, degree, school, project name, certification, etc.
    3. Updated `openLast(listId)`:
       - Uses `classList.add('open')` so newly created entry cards expand cleanly.
    4. Projects Section Rendering Fix (Live Preview, Preview Page, PDF):
       - Added GitHub/Repo URL (`github`) rendering in projects section.
       - Replaced raw full URL strings with clean, clickable link anchors (`Live` and `Source Code`).

  `templates/resume/preview.html`:
    - Renders project `url` as clickable `Live` text and project `github` as clickable `Source Code` text.

  `apps/resume/pdf_generator.py`:

1. SPAM MITIGATION & PROFESSIONAL EMAIL UPGRADE
   - Bug: The welcome/registration email was landing in spam folders when sent via basic SMTP (like Gmail).
   - Root Cause 1 (Domain Spoofing): `DEFAULT_FROM_EMAIL` was defaulting to `noreply@atsbuilder.com`.
     - Fix: Updated `ats_builder/settings.py` so that `DEFAULT_FROM_EMAIL` dynamically falls back to the `EMAIL_HOST_USER` if available. This guarantees the "From" address matches the authenticated SMTP user, preventing SPF/DMARC spoofing penalties.
   - Root Cause 2 (HTML-to-Text Mismatch): The plain-text fallback generated by `strip_tags` was unformatted and lacked the bullet points and footer present in the HTML version. Spam filters heavily penalize this mismatch.
     - Fix: Manually authored exact 1-to-1 plain-text fallback strings in `apps/accounts/utils.py` for both the OTP and Welcome emails.
   - Root Cause 3 (Localhost Links): The welcome email contained a hyperlink to `http://localhost:8000/dashboard/`. Email clients flag local/raw IP links as phishing.
     - Fix: Added an `is_local` check in `apps/accounts/utils.py`. If the app is running on localhost, the email removes the hyperlink and button, replacing it with text ("Please return to your browser"). On production (Vercel), the button renders normally.
   - Aesthetic Upgrade: Created professional HTML templates (`templates/emails/welcome.html`, `templates/emails/otp.html`, `templates/emails/base_email.html`) removing emojis and utilizing clean, corporate layouts with soft gray backgrounds, crisp sans-serif typography, and standard legal footers.
